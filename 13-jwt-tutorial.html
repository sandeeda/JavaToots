JWT Authentication
in Spring Boot

Build a working JWT auth system from scratch. Every file, every line explained. No steps skipped.

What we are building

A Spring Boot REST API where:

POST /auth/login
Public endpoint. User sends username + password. Gets back a JWT token.
↓
Client stores the token
And sends it on every future request inside the Authorization header.
↓
GET /api/orders (protected)
Token is validated by JwtFilter. If valid, request reaches controller. If not, 401.

How the pieces connect

Here is the complete picture before we write a single line of code:

① JwtUtil
Creates tokens on login. Validates + reads tokens on every request. Knows nothing about HTTP.
↓ used by
② JwtFilter (OncePerRequestFilter)
Runs on every HTTP request. Reads the Authorization header, calls JwtUtil to validate, puts user into SecurityContext.
↓ registered in
③ SecurityConfig
Wires everything together. Tells Spring Security which endpoints are public, registers JwtFilter into the chain, disables sessions.
↓ works alongside
④ AuthController
Handles /auth/login. Checks credentials, calls JwtUtil.generateToken(), returns token to client.
↓ protects
⑤ Your @RestControllers
Your actual business logic. Only reachable if JwtFilter put a valid user in SecurityContext.

Maven dependency — add this first

You need three things in your pom.xml: Spring Security, and the JJWT library (which handles JWT creation and parsing).

📄 pom.xml
<!-- Spring Security -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>

<!-- JJWT — the library that creates and parses JWT tokens -->
<!-- jjwt-api: the interfaces and classes you use in code -->
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-api</artifactId>
    <version>0.12.3</version>
</dependency>

<!-- jjwt-impl: the actual implementation — runtime only, not needed at compile time -->
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-impl</artifactId>
    <version>0.12.3</version>
    <scope>runtime</scope>
</dependency>

<!-- jjwt-jackson: lets JJWT use Jackson to read/write JSON inside tokens -->
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-jackson</artifactId>
    <version>0.12.3</version>
    <scope>runtime</scope>
</dependency>

Why three JJWT jars? JJWT splits itself into API + implementation. This is a common Java pattern — you code against the API, the impl does the actual work at runtime. You never import from jjwt-impl in your code.

application.yml — your config file

Store your JWT secret here. Never hardcode it directly in Java files.

📄 src/main/resources/application.yml
jwt:
  secret: 404E635266556A586E3272357538782F413F4428472B4B6250645367566B5970
  # This must be at least 256 bits (32 characters) for HMAC-SHA256
  # Generate your own with: openssl rand -hex 32
  expiration: 3600000
  # Token expiry in milliseconds — 3600000 = 1 hour

The application entry point — and how to actually run it

Every Spring Boot app needs exactly one class with a main() method. This is what Maven/your IDE actually executes.

📄 src/main/java/com/example/demo/DemoApplication.java
package com.example.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
// @SpringBootApplication = @Configuration + @EnableAutoConfiguration + @ComponentScan
// This single annotation is why JwtUtil, JwtFilter, SecurityConfig etc. all get
// picked up automatically — component scanning starts from this package down.
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
        // .run() starts the embedded Tomcat server, builds the ApplicationContext,
        // creates every @Component / @Service / @Configuration bean (including
        // the SecurityFilterChain from SecurityConfig), and starts listening
        // on port 8080 by default.
    }
}

How to start it: mvn spring-boot:run from the project root, or just run DemoApplication.main() from your IDE. Watch the console for Tomcat started on port(s): 8080 — that's your signal it's ready for the curl commands later in this tutorial.

Step 1

Project Structure

Organize your files before writing any code. This structure separates concerns cleanly.

src/main/java/com/example/demo/ │ ├── DemoApplication.java ← @SpringBootApplication, the main() entry point │ ├── auth/ ← login endpoint lives here │ ├── AuthController.java ← handles POST /auth/login │ └── LoginRequest.java ← request body (username + password) │ ├── config/ ← all Spring configuration │ └── SecurityConfig.java ← wires JWT filter into Spring Security │ ├── filter/ ← our custom filter │ └── JwtFilter.java ← reads token, validates, sets SecurityContext │ ├── orders/ ← example protected resource │ └── OrderController.java ← protected endpoint GET /api/orders │ └── util/ ← helper classes └── JwtUtil.java ← creates and validates tokens src/main/resources/ └── application.yml ← JWT secret and config

Why this structure?

1
auth/ — login only
Everything to do with authentication (login, register) lives here. Separated from your business logic.
2
config/ — Spring wiring
All @Configuration classes live here. Makes it easy to find where the app is configured.
3
filter/ — HTTP interceptors
Custom filters live here. In bigger apps you might have LoggingFilter, RateLimitFilter, etc. alongside JwtFilter.
4
util/ — reusable helpers
JwtUtil is a utility class. It has no HTTP knowledge — just pure token logic. Easy to test in isolation.

Build order matters. We build in this order: JwtUtil → JwtFilter → SecurityConfig → AuthController → OrderController. Each step depends on the previous one.

Step 2

JwtUtil — Token Factory

This class handles everything token-related. It creates tokens, validates them, and reads data from them. It knows nothing about HTTP requests.

What a JWT token actually looks like

A JWT is three Base64-encoded strings separated by dots:

// A real JWT token looks like this:
eyJhbGciOiJIUzI1NiJ9           ← HEADER  (algorithm info)
.
eyJzdWIiOiJzYW5kZWVwIiwiaWF0IjoxNjk5MDAwMDAwLCJleHAiOjE2OTkwMDM2MDB9
                                ← PAYLOAD (username, issued-at, expiry)
.
SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
                                ← SIGNATURE (proves nobody tampered with it)

// When decoded, the PAYLOAD contains:
{
  "sub": "sandeep",     ← subject = username
  "iat": 1699000000,  ← issued at (unix timestamp)
  "exp": 1699003600   ← expires at (1 hour later)
}

Important: The payload is NOT encrypted — anyone can decode it. The SIGNATURE is what proves the token is genuine. If someone modifies the payload, the signature won't match and validation fails.

The complete JwtUtil class

📄 src/main/java/com/example/demo/util/JwtUtil.java
package com.example.demo.util;

import io.jsonwebtoken.Claims;
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.security.Keys;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

import javax.crypto.SecretKey;
import java.util.Date;

@Component
// @Component makes Spring manage this as a bean so we can inject it anywhere
public class JwtUtil {

    @Value("${jwt.secret}")
    private String secret;
    // @Value reads the jwt.secret from application.yml and injects it here
    // Never hardcode secrets in Java files — always use config

    @Value("${jwt.expiration}")
    private long expiration;
    // Token expiry in milliseconds — read from application.yml
    // 3600000 = 1 hour

    // ─────────────────────────────────────────────────────────────────
    // PUBLIC METHODS — called by JwtFilter and AuthController
    // ─────────────────────────────────────────────────────────────────

    /**
     * Generates a JWT token for a given username.
     * Called by AuthController when user successfully logs in.
     *
     * @param username  the authenticated user's username
     * @return          the JWT token string
     */
    public String generateToken(String username) {
        return Jwts.builder()
            .subject(username)
            // .subject() sets the "sub" claim — who this token belongs to

            .issuedAt(new Date())
            // .issuedAt() sets the "iat" claim — when was this token created

            .expiration(new Date(System.currentTimeMillis() + expiration))
            // .expiration() sets the "exp" claim — when does this token expire
            // currentTimeMillis() = now in milliseconds
            // + expiration adds 1 hour (3600000 ms)

            .signWith(getSigningKey())
            // .signWith() creates the SIGNATURE using our secret key
            // This is what prevents tampering — only our server knows the secret

            .compact();
            // .compact() builds the final token string: "header.payload.signature"
    }

    /**
     * Extracts the username from a token.
     * Called by JwtFilter after it reads the token from the request header.
     *
     * @param token  the JWT token string
     * @return       the username stored inside the token
     */
    public String extractUsername(String token) {
        return parseClaims(token).getSubject();
        // parseClaims() decodes the token and returns all its data
        // .getSubject() reads the "sub" field — which is the username we stored
    }

    /**
     * Checks if a token is valid (genuine and not expired).
     * Called by JwtFilter to decide whether to allow the request.
     *
     * @param token  the JWT token string
     * @return       true if valid, false if expired or tampered
     */
    public boolean isTokenValid(String token) {
        try {
            parseClaims(token);
            // parseClaims() will throw an exception if:
            // - the signature doesn't match (token was tampered with)
            // - the token is expired (exp < now)
            // If no exception is thrown, the token is valid
            return true;
        } catch (Exception e) {
            // Any exception means the token is invalid
            // ExpiredJwtException   → token expired
            // SignatureException    → token was tampered with
            // MalformedJwtException → token is not a valid JWT format
            return false;
        }
    }

    // ─────────────────────────────────────────────────────────────────
    // PRIVATE METHODS — internal helpers
    // ─────────────────────────────────────────────────────────────────

    /**
     * Parses the token and returns all its claims (the payload data).
     * This method does the actual validation — it checks signature and expiry.
     * If anything is wrong, it throws an exception.
     */
    private Claims parseClaims(String token) {
        return Jwts.parser()
            .verifyWith(getSigningKey())
            // verifyWith() tells the parser which key to use to verify the signature

            .build()
            // build() creates the parser

            .parseSignedClaims(token)
            // parseSignedClaims() does the actual work:
            // 1. Decodes the Base64 header + payload
            // 2. Re-computes the signature using our secret key
            // 3. Compares it with the signature in the token
            // 4. Checks if expiry date has passed
            // Throws exception if any check fails

            .getPayload();
            // .getPayload() returns the Claims object — the actual data inside the token
    }

    /**
     * Converts the secret string from application.yml into a cryptographic key
     * that JJWT can use for signing and verification.
     */
    private SecretKey getSigningKey() {
        byte[] keyBytes = HexFormat.of().parseHex(secret);
        // Convert the hex string from application.yml into raw bytes
        // Our secret "404E635266..." is hex-encoded — HexFormat decodes it

        return Keys.hmacShaKeyFor(keyBytes);
        // Keys.hmacShaKeyFor() creates an HMAC-SHA key from the bytes
        // HMAC-SHA256 is the algorithm used to sign the token
    }
}

JwtUtil has no Spring Security imports. It only knows about tokens. This makes it easy to unit test — just create a new JwtUtil() and test generateToken() and isTokenValid() directly.

Step 3

JwtFilter — The Gatekeeper

This filter runs on every single HTTP request. Its job is to read the token, validate it, and tell Spring Security who the user is.

What it needs to do — step by step

1
Read the Authorization header
Every authenticated request should have: Authorization: Bearer <token>
2
Check header exists and starts with "Bearer "
If not — no token present. Pass the request along. Spring Security will handle unauthenticated access.
3
Strip "Bearer " to get the raw token
"Bearer eyJhbGci..." → "eyJhbGci..." (substring from index 7)
4
Call JwtUtil.isTokenValid()
If invalid or expired — pass along. SecurityContext stays empty. Spring Security returns 401.
5
Extract username from token
Call JwtUtil.extractUsername() to read who this token belongs to.
6
Put user into SecurityContext
Create a UsernamePasswordAuthenticationToken and set it in SecurityContextHolder. Spring Security will see this and allow the request.
7
Call chain.doFilter()
Always pass the request to the next filter in the chain.

The complete JwtFilter class

📄 src/main/java/com/example/demo/filter/JwtFilter.java
package com.example.demo.filter;

import com.example.demo.util.JwtUtil;
import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.security.web.authentication.WebAuthenticationDetailsSource;
import org.springframework.stereotype.Component;
import org.springframework.web.filter.OncePerRequestFilter;

import java.io.IOException;
import java.util.List;

@Component
// @Component registers this as a Spring bean so we can inject it into SecurityConfig
public class JwtFilter extends OncePerRequestFilter {
// extends OncePerRequestFilter — guarantees this runs EXACTLY once per request
// even if the request is internally forwarded within Spring

    private final JwtUtil jwtUtil;

    // Constructor injection — Spring injects JwtUtil automatically
    public JwtFilter(JwtUtil jwtUtil) {
        this.jwtUtil = jwtUtil;
    }

    /**
     * This method runs for every HTTP request.
     * We override doFilterInternal (not doFilter) because OncePerRequestFilter
     * handles the "run only once" guarantee for us. We just write our logic here.
     */
    @Override
    protected void doFilterInternal(
            HttpServletRequest request,
            HttpServletResponse response,
            FilterChain chain
    ) throws ServletException, IOException {

        // ── STEP 1: Read Authorization header ────────────────────────────
        String authHeader = request.getHeader("Authorization");
        // request.getHeader("Authorization") reads the value of the header
        // If the client sends: Authorization: Bearer eyJhbGci...
        // authHeader will be: "Bearer eyJhbGci..."
        // If the client sends no Authorization header, authHeader will be null

        // ── STEP 2: Check header exists and has Bearer token ─────────────
        if (authHeader == null || !authHeader.startsWith("Bearer ")) {
            // No token present in this request.
            // This is fine — maybe this is the /auth/login request,
            // or maybe the user is hitting a public endpoint.
            // We do NOT return 401 here — that's Spring Security's job.
            // We just pass the request along with an empty SecurityContext.
            chain.doFilter(request, response);
            return;
            // return here so we don't execute any code below
        }

        // ── STEP 3: Extract the raw token ────────────────────────────────
        String token = authHeader.substring(7);
        // "Bearer " is exactly 7 characters
        // substring(7) removes the first 7 characters
        // "Bearer eyJhbGci..." → "eyJhbGci..."

        // ── STEP 4: Validate the token ───────────────────────────────────
        if (!jwtUtil.isTokenValid(token)) {
            // Token is invalid (expired, tampered, malformed).
            // Again — we don't return 401 directly.
            // We just pass along with an empty SecurityContext.
            // Spring Security's AuthorizationFilter will return 401.
            chain.doFilter(request, response);
            return;
        }

        // ── STEP 5: Extract username from the token ──────────────────────
        String username = jwtUtil.extractUsername(token);
        // At this point the token is valid, so we can trust the username inside it
        // username will be something like "sandeep"

        // ── STEP 6: Check SecurityContext is not already set ─────────────
        if (SecurityContextHolder.getContext().getAuthentication() == null) {
            // We only set authentication if it's not already set.
            // In theory, no other filter should have set it before us,
            // but this is a safety check to avoid overwriting valid auth.

            // ── STEP 7: Create the authentication object ─────────────────────
            UsernamePasswordAuthenticationToken authToken =
                new UsernamePasswordAuthenticationToken(
                    username,       // principal — who the user is (the username string)
                    null,           // credentials — we don't need the password here, token proved identity
                    List.of()       // authorities — roles (empty for now, add roles here later)
                );

            authToken.setDetails(
                new WebAuthenticationDetailsSource().buildDetails(request)
            );
            // setDetails() attaches extra info like the user's IP address
            // and the session ID to the authentication object.
            // Not required, but good practice — useful for audit logging.

            // ── STEP 8: Set authentication in SecurityContext ─────────────────
            SecurityContextHolder.getContext().setAuthentication(authToken);
            // SecurityContextHolder is a thread-local storage.
            // "Thread-local" means each request thread has its own copy.
            // So setting auth here doesn't affect other concurrent requests.
            //
            // This is the KEY line — Spring Security's AuthorizationFilter
            // checks SecurityContextHolder.getContext().getAuthentication()
            // If it's not null and isAuthenticated() is true → request is allowed
            // If it's null → 401 Unauthorized
        }

        // ── STEP 9: Always pass request to next filter ───────────────────
        chain.doFilter(request, response);
        // We ALWAYS call this — even after setting auth.
        // The request must continue through the filter chain.
        // After this line, everything downstream runs (other filters, controller).
        // When they all finish and return, execution comes back here and the
        // method ends, sending the response back to the client.
    }

    /**
     * Tell OncePerRequestFilter to SKIP this filter for /auth/** paths.
     * These are public endpoints — user doesn't have a token yet.
     * No need to even try reading a token for login/register requests.
     */
    @Override
    protected boolean shouldNotFilter(HttpServletRequest request) {
        String path = request.getRequestURI();
        return path.startsWith("/auth/");
        // return true = skip this filter for this request
        // return false = run this filter (default behaviour)
    }
}

Three scenarios — what happens in each case

Scenario A No Authorization header
Request: GET /api/orders
         (no Authorization header)
   ↓
JwtFilter:
   authHeader == null → chain.doFilter() → return
   ↓
SecurityContext: empty
   ↓
Spring Security: 401 Unauthorized
Scenario B Expired or invalid token
Request: GET /api/orders
         Authorization: Bearer expiredToken123
   ↓
JwtFilter:
   header exists, starts with Bearer ✓
   token = "expiredToken123"
   jwtUtil.isTokenValid(token) → false (expired)
   → chain.doFilter() → return
   ↓
SecurityContext: empty
   ↓
Spring Security: 401 Unauthorized
Scenario C Valid token
Request: GET /api/orders
         Authorization: Bearer validToken456
   ↓
JwtFilter:
   header exists, starts with Bearer ✓
   token = "validToken456"
   jwtUtil.isTokenValid(token) → true ✓
   username = "sandeep"
   SecurityContextHolder.getContext().setAuthentication(authToken) ✓
   → chain.doFilter()
   ↓
SecurityContext: Authentication { principal: "sandeep", authenticated: true }
   ↓
Spring Security: allows through ✓
   ↓
OrderController.getOrders() runs ✓
Step 4

SecurityConfig — Wiring It Together

This is where you register JwtFilter into Spring Security's chain and define which endpoints are public vs protected.

Spring Boot 3+ only. The old WebSecurityConfigurerAdapter is removed in Spring Boot 3. You now use a SecurityFilterChain bean instead. If you are on Spring Boot 2.x the syntax is different.

The complete SecurityConfig class

📄 src/main/java/com/example/demo/config/SecurityConfig.java
package com.example.demo.config;

import com.example.demo.filter.JwtFilter;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.config.annotation.authentication.configuration.AuthenticationConfiguration;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configuration.EnableWebSecurity;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.security.web.SecurityFilterChain;
import org.springframework.security.web.authentication.UsernamePasswordAuthenticationFilter;

@Configuration
// @Configuration tells Spring: this class contains @Bean definitions
// Spring reads this class on startup and creates all the beans defined inside

@EnableWebSecurity
// @EnableWebSecurity activates Spring Security's web security support
// Without this, Spring Security won't protect your endpoints

public class SecurityConfig {

    private final JwtFilter jwtFilter;

    public SecurityConfig(JwtFilter jwtFilter) {
        this.jwtFilter = jwtFilter;
        // JwtFilter is injected here by Spring (it's a @Component)
        // We need it so we can register it in the security filter chain below
    }

    /**
     * The main security configuration bean.
     * This defines the entire security behaviour of your app:
     * - which endpoints are public
     * - which need authentication
     * - what kind of auth (JWT in our case)
     * - session management
     */
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {

        http

            // ── CSRF: disable ────────────────────────────────────────────────
            .csrf(csrf -> csrf.disable())
            // CSRF = Cross Site Request Forgery
            // CSRF protection is needed for session-based apps where browsers
            // automatically send cookies. With JWT, the client manually sets
            // the Authorization header — a malicious site cannot do this.
            // So CSRF protection is not needed and we disable it.

            // ── Sessions: stateless ──────────────────────────────────────────
            .sessionManagement(session -> session
                .sessionCreationPolicy(SessionCreationPolicy.STATELESS)
            )
            // STATELESS means Spring Security will NOT create HTTP sessions.
            // Each request must prove its identity via JWT — there is no
            // "remember me between requests" on the server side.
            // This makes our API scalable — any server instance can handle
            // any request because no session state is stored server-side.

            // ── Endpoint authorization rules ─────────────────────────────────
            .authorizeHttpRequests(auth -> auth

                .requestMatchers("/auth/**").permitAll()
                // /auth/login, /auth/register etc. are public — no token needed
                // ** means "any path starting with /auth/"

                .requestMatchers("/actuator/health").permitAll()
                // Health check endpoint — Kubernetes/load balancers need this without auth

                .anyRequest().authenticated()
                // Every other endpoint requires authentication
                // If SecurityContext is empty → Spring Security returns 401
                // If SecurityContext has a user (set by JwtFilter) → request allowed
            )

            // ── Register our JwtFilter ───────────────────────────────────────
            .addFilterBefore(jwtFilter, UsernamePasswordAuthenticationFilter.class);
            // addFilterBefore(A, B) = run A before B in the filter chain
            //
            // UsernamePasswordAuthenticationFilter is Spring Security's default
            // filter that handles form-based login. We don't use it (we use JWT),
            // but we use it as a position marker to insert our filter before it.
            //
            // Spring Security's internal filter chain order (simplified):
            //   ... → JwtFilter (ours) → UsernamePasswordAuthenticationFilter → AuthorizationFilter → ...
            //
            // By the time AuthorizationFilter checks SecurityContext,
            // our JwtFilter has already validated the token and set the user.

        return http.build();
        // .build() creates the SecurityFilterChain bean from the configuration above
    }

    /**
     * AuthenticationManager bean.
     * Used by AuthController to authenticate username/password during login.
     * Spring Security provides this — we just expose it as a bean.
     */
    @Bean
    public AuthenticationManager authenticationManager(
            AuthenticationConfiguration config) throws Exception {
        return config.getAuthenticationManager();
        // AuthenticationManager is what actually checks username + password
        // It delegates to UserDetailsService to load the user,
        // then checks the password using PasswordEncoder
    }

    /**
     * PasswordEncoder bean.
     * BCrypt is the standard password hashing algorithm.
     * NEVER store plain text passwords — always hash them.
     * BCrypt adds a random "salt" so the same password hashes differently each time.
     */
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}

Where JwtFilter sits in the chain

SecurityContextPersistenceFilter
Spring's built-in — loads/saves SecurityContext per request
↓
JwtFilter ← YOUR FILTER GOES HERE
Reads token → validates → sets SecurityContext
↓
UsernamePasswordAuthenticationFilter

↓

↓

Step 5

AuthController — The Login Endpoint

This is the only public endpoint. The user sends their credentials here and gets back a JWT token.

LoginRequest — the request body class

First we need a simple class to hold what the client sends:

📄 src/main/java/com/example/demo/auth/LoginRequest.java
package com.example.demo.auth;

public class LoginRequest {

    private String username;
    private String password;

    // Default constructor — required for Jackson to deserialize JSON into this object
    public LoginRequest() {}

    public String getUsername() { return username; }
    public void setUsername(String username) { this.username = username; }

    public String getPassword() { return password; }
    public void setPassword(String password) { this.password = password; }
}

The AuthController

📄 src/main/java/com/example/demo/auth/AuthController.java
package com.example.demo.auth;

import com.example.demo.util.JwtUtil;
import org.springframework.http.ResponseEntity;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.authentication.BadCredentialsException;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.Authentication;
import org.springframework.web.bind.annotation.*;

import java.util.Map;

@RestController
@RequestMapping("/auth")
public class AuthController {

    private final AuthenticationManager authenticationManager;
    private final JwtUtil jwtUtil;

    public AuthController(AuthenticationManager authenticationManager,
                          JwtUtil jwtUtil) {
        this.authenticationManager = authenticationManager;
        this.jwtUtil = jwtUtil;
    }

    @PostMapping("/login")
    public ResponseEntity<Map<String, String>> login(@RequestBody LoginRequest request) {

        try {
            // ── STEP 1: Authenticate username and password ────────────────────
            Authentication authentication = authenticationManager.authenticate(
                new UsernamePasswordAuthenticationToken(
                    request.getUsername(),   // username from request body
                    request.getPassword()    // password from request body
                )
            );
            // authenticationManager.authenticate() does the following:
            // 1. Calls UserDetailsService.loadUserByUsername(username)
            //    to load the user from your database (or in-memory store)
            // 2. Compares the provided password with the stored hashed password
            //    using PasswordEncoder (BCrypt in our case)
            // 3. If credentials are correct → returns Authentication object
            // 4. If credentials are wrong → throws BadCredentialsException

            // ── STEP 2: Generate JWT token ────────────────────────────────────
            String username = authentication.getName();
            // authentication.getName() returns the username of the authenticated user

            String token = jwtUtil.generateToken(username);
            // Generate a JWT token with the username embedded in it
            // This token is valid for 1 hour (as configured in application.yml)

            // ── STEP 3: Return token to client ───────────────────────────────
            return ResponseEntity.ok(
                Map.of("token", token)
            );
            // Response body: { "token": "eyJhbGci..." }
            // The client stores this and sends it on every future request

        } catch (BadCredentialsException e) {
            // Wrong username or password
            // Return 401 with a clear error message
            return ResponseEntity
                .status(401)
                .body(Map.of("error", "Invalid username or password"));
        }
    }
}

But wait — where do users come from?

The AuthenticationManager needs a UserDetailsService to load users. For this tutorial we use an in-memory user. In a real app you load from a database.

Add this bean to SecurityConfig: This creates a user "sandeep" with password "password" stored in memory.

📄 SecurityConfig.java — add this bean
// Add this inside SecurityConfig class

@Bean
public UserDetailsService userDetailsService(PasswordEncoder passwordEncoder) {
    UserDetails user = User.builder()
        .username("sandeep")
        .password(passwordEncoder.encode("password"))
        // passwordEncoder.encode() hashes the password with BCrypt
        // We never store plain text — even in-memory users use hashed passwords
        .roles("USER")
        .build();

    return new InMemoryUserDetailsManager(user);
    // InMemoryUserDetailsManager holds users in memory
    // In a real app: implement UserDetailsService and load from your DB
}
Step 6

Protected Controller — Your Actual API

This is a normal @RestController. It does nothing special for JWT. The filter has already done all the auth work before this runs.

📄 src/main/java/com/example/demo/orders/OrderController.java
package com.example.demo.orders;

import org.springframework.http.ResponseEntity;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.web.bind.annotation.*;

import java.util.List;
import java.util.Map;

@RestController
@RequestMapping("/api")
public class OrderController {

    /**
     * GET /api/orders
     * Protected endpoint — only reachable with a valid JWT token.
     * JwtFilter has already validated the token and set the user
     * in SecurityContext before this method ever runs.
     */
    @GetMapping("/orders")
    public ResponseEntity<Map<String, Object>> getOrders() {

        // How to get the currently logged-in user inside a controller:
        Authentication auth = SecurityContextHolder.getContext().getAuthentication();
        String username = auth.getName();
        // auth.getName() returns the username we stored in SecurityContext
        // back in JwtFilter — which was extracted from the JWT token

        return ResponseEntity.ok(Map.of(
            "user", username,
            "orders", List.of("Order #1001", "Order #1002", "Order #1003")
        ));
    }

    /**
     * Alternative: use @AuthenticationPrincipal to inject the user directly
     * Spring resolves this from SecurityContextHolder automatically
     */
    @GetMapping("/me")
    public ResponseEntity<String> whoAmI(
            @AuthenticationPrincipal String username) {
        // @AuthenticationPrincipal is a shortcut for:
        // SecurityContextHolder.getContext().getAuthentication().getPrincipal()
        // In our case the principal is the username string we passed to
        // UsernamePasswordAuthenticationToken in JwtFilter
        return ResponseEntity.ok("Hello, " + username);
    }
}

Full Request Flow — Everything Together

Two complete traces showing exactly what happens from browser to controller and back.

Flow A — Login (getting a token)

Client: POST /auth/login
Body: { "username": "sandeep", "password": "password" }
↓
Tomcat receives the HTTP request
Parses the raw HTTP text into an HttpServletRequest Java object
↓
JwtFilter.doFilterInternal()
shouldNotFilter() returns true for /auth/ path → filter is SKIPPED entirely → chain.doFilter() called immediately
↓
Spring Security: AuthorizationFilter
/auth/login matches .permitAll() rule → allowed without authentication
↓
DispatcherServlet
Looks up handler map → finds AuthController.login() for POST /auth/login
↓
AuthController.login() runs
authenticationManager.authenticate() → checks "sandeep" / "password" → valid ✓ → jwtUtil.generateToken("sandeep") → returns { "token": "eyJ..." }
↓
Client receives token
Stores it. Will send it on every future request in the Authorization header.

Flow B — Accessing a protected endpoint

Client: GET /api/orders
Header: Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
↓
Tomcat receives the HTTP request
Wraps in HttpServletRequest, passes to filter chain
↓
JwtFilter.doFilterInternal() — RUNS
shouldNotFilter() → false (not /auth/ path) → filter runs
↓
JwtFilter: reads Authorization header
authHeader = "Bearer eyJhbGci..." → starts with "Bearer " ✓ → token = "eyJhbGci..."
↓
JwtFilter: validates token
jwtUtil.isTokenValid(token) → parseClaims() → signature OK ✓ → not expired ✓ → returns true
↓
JwtFilter: extracts username
jwtUtil.extractUsername(token) → parseClaims().getSubject() → "sandeep"
↓
JwtFilter: sets SecurityContext
new UsernamePasswordAuthenticationToken("sandeep", null, []) → SecurityContextHolder.getContext().setAuthentication(authToken)
↓
JwtFilter: chain.doFilter() — passes to next filter
JwtFilter is now waiting for everything downstream to finish
↓
Spring Security: AuthorizationFilter
SecurityContextHolder.getContext().getAuthentication() → not null, isAuthenticated() = true ✓ → ALLOWS request
↓
DispatcherServlet
Finds OrderController.getOrders() for GET /api/orders
↓
OrderController.getOrders() runs
SecurityContextHolder.getContext().getAuthentication().getName() → "sandeep" → returns orders list
↓
Response travels back up through filters
JwtFilter resumes after chain.doFilter() returns → method ends → response sent to client
↓
Client receives: 200 OK
{ "user": "sandeep", "orders": ["Order #1001", "Order #1002", "Order #1003"] }

Summary — every class and its job

Class Job Called by
JwtUtil Creates tokens, validates tokens, extracts username. Pure logic, no HTTP. JwtFilter, AuthController
JwtFilter Runs on every request. Reads header → validates → sets SecurityContext. Spring Security (automatically)
SecurityConfig Registers JwtFilter. Defines public vs protected endpoints. Disables sessions. Spring Boot (on startup)
AuthController Handles POST /auth/login. Checks credentials. Returns token. Client (browser/Postman)
OrderController Your actual business logic. Reads username from SecurityContext. Client (after auth)
LoginRequest DTO — holds username + password from request body JSON. AuthController

You built a complete JWT system. Every request is now stateless — no sessions, no cookies. The token proves identity on every call. The server only needs the secret key to verify any token it issues.
